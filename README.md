# Folio — 나의 전자책 스튜디오

한국어 원고를 편집하고, 교정·윤문·표지·삽화를 적용한 뒤 EPUB 3, 인쇄용 PDF, 단일 HTML로 제작하는 개인 전자책 웹앱입니다.

## GitHub Pages 배포

이 저장소는 공개 소스와 공개 웹앱 배포용입니다. 방문자마다 자신의 브라우저에 원고를 보관하며, API 키는 현재 탭 메모리에서만 사용합니다. 서버에 원고를 자동 업로드하지 않습니다. 다른 사람·기기와 작업하려면 공유 범위에 동의한 뒤 공유 파일을 직접 전달합니다.

저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 설정하면 `main`에 푸시할 때 앱·연결 도우미 검사와 고정 버전 EPUBCheck 표준 검증을 통과한 결과를 자동 배포합니다. 처음에는 **Actions → Verify and deploy Folio → Run workflow**로도 실행할 수 있습니다. 배포 주소는 `github-pages` 환경에서 확인할 수 있습니다.

Windows 연결 도우미는 배포 시 실제 Pages 출처에 맞춰 패키징합니다. **배포된 앱 안의 다운로드 버튼**으로 받으세요. GitHub Pages의 저장소 경로를 포함한 주소에서도 상대 경로로 앱·이미지·다운로드를 불러옵니다. API 키나 별도 서버 비밀값은 GitHub Actions에 등록하지 않습니다.

기존 비공개 사이트와 GitHub Pages는 브라우저 저장 공간이 다릅니다. 기존 사이트에서 **현재 책 백업** 또는 **서재 전체 백업(JSON)**을 받은 뒤 새 사이트의 **가져오기**로 옮기세요. 원고가 자동으로 이전되지는 않으며 API 키도 다시 연결해야 합니다.

## 바로 사용하기

내 서재에서 **새 전자책**을 만들거나 TXT / Markdown / DOCX / EPUB / Folio JSON 원고를 가져옵니다. 기본 화면은 Markdown이 렌더링된 **프리뷰**입니다. **편집**에서 수정하고 다시 프리뷰로 돌아와 확인한 뒤 윤문·교정 → 표지 & 삽화 → 출판·내보내기 순서로 작업합니다.

- Markdown 원고의 제목을 기준으로 최대 1,000개 장을 나눠 가져옵니다. 300장 원고도 장별 제목과 본문을 유지합니다. 1,000개를 넘는 제목은 마지막 장 본문에 남깁니다. 책의 메타데이터와 제작 진행까지 복원하려면 JSON 백업을 사용하세요.
- 글은 이 브라우저의 IndexedDB에 자동 저장됩니다. 사용할 수 없으면 localStorage를 사용합니다. 저장 데이터가 손상됐거나 다른 탭에서 먼저 저장했으면 덮어쓰기를 멈추고 백업 버튼을 표시합니다. 다른 기기로 옮기거나 브라우저 데이터를 지우기 전 **작업 백업(JSON)**을 내려받으세요.
- 설정에서 **현재 책 백업** 또는 **서재 전체 백업**을 받을 수 있습니다. 서재 전체 백업에는 모든 책과 최근 수정 이력이 들어가며, 가져올 때 기존 책을 유지한 채 새 책으로 추가합니다. JSON 가져오기는 128MiB까지 지원합니다. 이를 넘는 전체 백업에는 별도 안내를 표시하므로 책별 백업도 보관하세요. 저장소 원본 보관 파일은 손상·충돌 조사용이며 일반 작업 파일과 구분됩니다.
- 원고를 바꾸는 자동 작업 전에는 수정 이력을 저장합니다. 최근 8개 상태로 복원할 수 있습니다.
- 기본 자동 정리는 보수적인 공백·표기 교정과 테마별 그래픽 삽화를 적용합니다. 창작·의미 수정은 하지 않습니다.
- AI 기능은 설정에서 **Google Gemini** 또는 **OpenAI**를 선택하고 본인의 API 키를 연결한 뒤 사용합니다. 기본 제공자는 Google Gemini입니다. Google 키는 [Google AI Studio](https://aistudio.google.com/apikey)에서 발급받습니다. 키는 현재 탭 메모리에만 저장되며, 새로고침 시 사라집니다. 앱 서버에 전송하거나 저장하지 않습니다. 제공자를 바꾸면 기존 키와 검증 요청을 초기화합니다.
- Google 기본 모델은 글쓰기 `gemini-3.8-flash`, 이미지 `gemini-nano-banana-2.1`입니다. OpenAI는 `gpt-4.1`, `gpt-image-1`을 사용합니다. 계정에서 접근 가능한 모델명으로 변경할 수 있습니다. 모델과 사용량에 따라 제공자별 API 비용이 발생할 수 있으며, 소비자용 AI 구독과 별개입니다.
- 연결 확인은 글쓰기 모델의 접근 권한만 조회하며 콘텐츠를 생성하지 않습니다. Google이 반환한 모델별 출력 한도가 있으면 글쓰기 요청에 반영합니다. 이미지 모델의 접근 권한·결제·잔여 한도는 실제 생성 시 확인됩니다. Google Gemini Developer API를 사용하며, Maps 키나 Vertex AI 서비스 계정 파일은 지원하지 않습니다.
- 연결 후 설정을 다시 열어 **실제 생성 테스트**를 누르면 짧은 예문을 한 번 생성합니다. 응답과 사용 모델을 표시하며, 원고를 전송하거나 수정하지 않습니다. 텍스트 요청 1회의 API 비용이 발생할 수 있습니다. 이 테스트는 이미지 권한이나 300장 전체 집필 품질을 확인하지는 않습니다.
- AI 기획·집필·윤문에는 자연스러운 문체 기준을 기본 적용합니다. 상투적인 도입·결론, 과장된 수식, 반복 구조를 줄이고 원문의 말투·사실·인용을 보존하도록 요청합니다. 같은 생성 요청 안에서 문장을 한 번 더 검토하며, 이를 위한 추가 API 요청은 없습니다.
- **윤문 · 교정 → 원하는 말투와 참고 문장**에서 문체 요청과 본인이 쓴 문장을 입력할 수 있습니다. 참고 문장은 말투를 맞추는 용도로만 사용하며, 저장·백업·복원에 포함됩니다.
- AI 윤문은 장마다 12,000자까지 지원합니다. 500자 이상의 원고가 60% 미만으로 줄거나 두 배를 넘게 늘어난 결과는 적용하지 않습니다. 수치·직접 인용의 변경을 감지하면 원고 옆과 윤문 화면에 비교 검토 메모를 표시합니다. 이는 사실 검증이 아니며 의미 손실을 모두 잡지는 못합니다.
- **AI 자동 제작**은 등록한 원시 자료 또는 현재 원고를 집필 조건으로 가져옵니다. 조건을 저장하면 기존 책을 유지한 채 별도의 제작 책을 만듭니다. 견적을 확인하고 승인한 뒤에만 자료 분석·목차·본문·선택한 삽화를 생성합니다. 기존 원고를 직접 다듬으려면 장별 **AI 윤문**을 사용하세요.
- 이미지는 파일로 올리거나 앱 안에서 생성합니다. 외부 이미지 URL을 포함한 백업은 추적 요청을 막기 위해 가져오기·출력에서 거부합니다. 업로드 한도는 8MiB, 이미지 구조 검사 한도는 장당 12MiB·5천만 화소, 책의 출력 이미지 합계는 128MiB입니다. 지원 파일은 PNG/JPEG/WebP이며 앱의 SVG 삽화는 제한된 안전한 요소로 재구성합니다.
- PDF 버튼은 브라우저 인쇄 창을 엽니다. **PDF로 저장**, 배경 그래픽 켜기, 머리글·바닥글 끄기를 권장합니다. EPUB은 표준 전자책 리더에서 파일을 열어 확인하세요.

AI 결과의 사실·인용·표현은 출판 전 저자가 검토해야 합니다. 출판 준비도는 원고 구조·기본 표기·메타데이터 점검으로 산정하며 문학적 품질의 평가가 아닙니다.

## DOCX와 EPUB 원고 가져오기

**원고 가져오기 / 작업 가져오기**에서 DOCX 또는 EPUB을 선택하면 현재 책을 유지하고 편집 가능한 새 책으로 변환합니다. 장 순서, 제목, 본문, 기본 강조, 지원 래스터 이미지와 텍스트 주석을 가져옵니다. **가져오기 보고서**에서 변환 경고를 확인하고 원본과 프리뷰를 비교하세요.

- 원본 DOCX/EPUB 파일을 작업 데이터와 JSON 백업에 그대로 보관합니다. **원본 파일 받기**로 다시 내려받을 수 있습니다. 변환된 책을 편집해도 원본 문서는 변경하지 않습니다.
- 파일은 최대 16MiB, 압축 해제 합계 48MiB, 압축 항목 1200개까지 처리합니다. 손상된 압축 파일, 경로 이탈, 암호화, 스크립트·외부 자료 의존은 차단합니다. 오류나 취소 시 기존 책은 유지합니다.
- DOCX의 병합 셀·여백·글꼴·부동 개체·변경 이력을 그대로 재현하지 않습니다. EPUB은 읽기 순서(spine)를 따르며 CSS·고정 레이아웃·SVG 삽화·수식 배치·복잡한 표는 편집용 텍스트로 변환하거나 제외하고 경고를 남깁니다.
- DOCX 번호 목록은 시작 번호·재시작·다단계 라벨·로마자/알파벳을 본문 라벨로 보존합니다. 목록 전용 접근성 구조와 정밀 들여쓰기는 변환 경고를 확인해 주세요.
- 각주·미주는 텍스트로 보존합니다. 원래 문서의 모든 상호 링크나 정밀 조판을 복원하는 기능은 아닙니다. 기존 EPUB의 내부 XHTML/CSS/OPF를 직접 수정하려면 Sigil 또는 calibre 같은 도구를 함께 사용하세요.

## 새 책에 원시 소스 등록하기

**새 전자책 만들기**에서 참고할 원시 소스를 붙여 넣거나 UTF-8 TXT/Markdown 파일, Markdown·이미지 여러 파일, 폴더를 등록할 수 있습니다. 등록한 자료는 원래 문서의 BOM·줄바꿈과 파일 목록을 보관하며, **기존 원고** 입력란과 구분합니다. 기존 원고는 편집할 장으로 나뉘고 원시 소스는 참고 자료로 따로 저장됩니다. 등록만으로는 AI 요청이나 비용이 발생하지 않습니다.

생성한 책의 자료 카드에서 내용을 확인하거나 **자료로 새 책 집필**을 선택하세요. 원시 자료와 기존 책은 보존하며, 새 제작 책에서 아래 승인 절차를 진행합니다. 원시 소스와 출판 정보는 책 JSON 백업·가져오기에도 포함됩니다.

## 주제와 원시 자료로 책 만들기

상단 **조건으로 책 만들기**에서 주제, 원시 Markdown, 집필 지시, 목표 분량을 한곳에 입력합니다. 필요한 독자·문체·언어·장 수·삽화 방식도 정할 수 있습니다.

1. 저자명을 입력하고 원시 MD를 붙여 넣거나 **원고 폴더 불러오기**로 폴더를 선택합니다. 폴더 아래의 모든 하위 폴더까지 `.md`, `.markdown`과 PNG·JPEG·WebP 이미지를 모읍니다. 주제를 비워 두면 자료를 바탕으로 구성하며, 이미지만으로 시작할 수도 있습니다. **MD·이미지 파일 여러 개 선택**과 UTF-8 `.md`, `.markdown`, `.txt` 파일 하나 불러오기도 지원합니다. Markdown 원시 자료는 최대 120,000자이며, 업로드한 원문의 BOM·줄바꿈·들여쓰기를 그대로 별도 보관합니다. 화면에서 직접 편집한 뒤에는 그 편집값을 사용합니다.
2. 포함할 내용, 제외할 내용, 구성 방식 등을 **집필 지시**에 적습니다. 원시 문서 안의 명령문은 자료로 취급하고, 별도로 입력한 제작 지시를 집필 기준으로 사용합니다.
3. 목표 본문은 공백 제외 **3,000~300,000자**로 정합니다. **예상 4~375쪽**으로 입력하면 쪽당 800자로 환산합니다. 일반 Markdown 기호는 글자 수에 포함되며, 생성 도표는 JSON 문법 대신 제목·캡션·표시 데이터를 셉니다. EPUB의 읽기 설정과 PDF 조판에 따라 실제 쪽수는 달라집니다. 장 수는 **2~300장(챕터)**을 직접 정하거나, 0을 입력해 자동 구성합니다(자동은 최대 40장). 한 장에 최소 500자가 필요하므로 **300장은 최소 150,000자 또는 예상 188쪽**으로 설정하세요. 분량이 부족하면 안내 아래 버튼으로 최소 분량을 적용할 수 있습니다.
4. **제작 조건 저장**을 누르면 기존 책과 별개인 새 책으로 보관하며, AI 요청은 보내지 않습니다. 검토 화면에서 Google Gemini 또는 OpenAI를 연결한 다음 **제작 시작**을 눌러 견적을 엽니다. 일반 책의 예상 쪽수, 소요시간 범위, 달러·원화 비용과 적용 모델·단가·환율을 확인하세요. 확인란을 선택하고 **승인하고 집필 시작**을 눌러야 주제·지시·자료가 선택한 제공자로 전송되고 유료 API 요청이 시작됩니다.
5. 자료 분석 → 목차 구성 → 본문 집필 → 표지·삽화의 진행률과 저장된 장·구간 수, 집필 글자 수를 표시합니다. 경과시간과 남은 시간·달러/원화 비용 추정도 갱신합니다. 진행률은 저장된 완료 단계에 기반하므로 응답을 기다리는 동안 멈춰 있을 수 있습니다. 자료 전체를 나누어 읽고 목차를 구성한 뒤, 짧은 구간을 차례로 집필합니다. **40장을 넘는 책은 목차를 20장씩 생성·저장**합니다. 300장이라면 목차 요청은 15회이며, 중단 후에는 저장된 목차부터 이어갑니다. 집필 요청에는 전체 목차 제목과 인접 장의 상세 개요를 전달합니다. 구간별 목표 ±10%를 벗어나면 한 번 보정합니다. 계속 벗어나면 원고를 자르거나 분량을 채우지 않고 **검토 필요**로 표시하며, 사용자가 다시 보정을 요청할 수 있습니다. 이는 글자 수 제어이며 사실·문학적 완성도 검증이 아닙니다.
6. 완료한 단계마다 저장합니다. 중지·연결 오류·새로고침 후에는 API 키를 다시 연결하여 **이어서 제작**할 수 있습니다. 재개·재보정도 남은 작업의 견적을 확인하고 새로 승인해야 하며, 모델이나 조건을 바꾸면 이전 승인을 재사용하지 않습니다. 직접 편집한 원고가 감지되면 덮어쓰지 않고 중단하므로, **이 조건으로 새 책**으로 다시 시작하세요. 현재 책 백업(JSON)에 원시 자료·지시·진행 기록도 포함됩니다.

**분량과 견적 읽기:** 30,000자는 일반적인 본문 밀도 기준 약 **30~50쪽**입니다(쪽당 공백 제외 600~1,000자 가정). 800자/쪽을 기준으로 보면 약 38쪽, 200쪽 책의 약 19%입니다. 그림·글꼴·화면 크기에 따라 실제 쪽수는 달라집니다. 견적은 토큰 수와 요청 시간의 범위 추정이며 결제액이나 최대 지출 한도가 아닙니다. 확인일이 표시된 환율·공식 단가를 사용하고, **환율·단가 직접 조정**에서 바꿀 수 있습니다. 조정 후에는 **변경한 기준으로 다시 계산**을 눌러 다시 승인하세요. 가격을 알 수 없는 모델은 직접 단가를 입력하기 전 집필 승인이 비활성화됩니다.

기본 그림은 이미지 API를 사용하지 않는 디자인 삽화입니다. AI 이미지를 선택하면 표지 1장과 본문 최대 2장을 생성하고, 실패한 이미지 작업은 완료된 본문을 보존한 채 이어갈 수 있습니다. 작업 중에는 탭을 열어 두세요. 브라우저를 닫으면 진행 중인 응답은 사라질 수 있지만 이미 저장된 결과는 유지됩니다.

### 문맥에 필요한 도표

- **설명에 필요한 도표 → 문맥에 맞게 자동 판단**이 기본입니다. 집필·윤문 중 비교표, 절차 흐름도, 막대·꺾은선 차트를 적절한 문단에 넣습니다. 도표가 도움이 되지 않으면 만들지 않으며, **새 도표 생성 안 함**으로 끌 수 있습니다.
- 기존 원고에서는 **원고 편집 → 도표 보강**을 누르세요. 글쓰기 모델 요청 1회로 검토해 필요한 경우 한 개를 추가합니다. 변경 전 원고는 수정 이력에 남고, 검토 중 취소하거나 문맥에 도표가 필요 없으면 추가하지 않습니다.
- 막대·꺾은선 차트는 각 항목·수치·단위를 포함한 인용문이 입력 자료에 있는지 검사합니다. 새로 생성한 글이나 도표 자체를 숫자의 근거로 삼지 않습니다. 이는 자료 일치 검사이며 자료의 사실성·이미지 분석 정확성 검증은 아닙니다. 정성 비교표와 흐름도의 의미도 독자가 읽기 전에 확인하세요.
- 도표는 장마다 최대 12개입니다. 집필 응답 하나에는 새 도표를 최대 한 개만 추가하고, 자동 집필에 별도 도표 요청이나 이미지 생성 비용을 더하지 않습니다. 텍스트 생성 사용량에는 도표 자료가 포함됩니다.
- **읽기 모드·책 미리보기·EPUB·HTML·PDF 인쇄**에 같은 도표가 반영됩니다. 차트에는 수치 표와 근거를 함께 표시합니다. 일반 Markdown 표도 지원합니다. JSON 백업과 Markdown 파일에는 편집 가능한 `folio-diagram` 블록이 보존됩니다.

### 폴더의 원고를 한 번에 반영하기

- **조건으로 책 만들기 → 원고 폴더 불러오기**에서 가장 위의 폴더를 선택하세요. 그 아래 여러 단계로 중첩된 폴더의 Markdown과 PNG·JPEG·WebP 이미지도 포함됩니다. PDF·TXT·SVG·GIF 등 지원하지 않는 형식은 읽지 않으며 제외 개수를 표시합니다.
- 경로를 기준으로 숫자 순서(1, 2, 10)를 고려해 정렬합니다. 같은 파일명도 하위 경로가 다르면 각각 포함합니다. 합친 원시 MD에 파일별 경로 구분을 넣고, **반영한 Markdown · 파일 경로와 순서**에서 전체 목록을 확인할 수 있습니다.
- 한 번에 Markdown 최대 500개, 합계 1MiB, 경로 구분을 포함해 120,000자까지 지원합니다. 한도 초과·잘못된 UTF-8·읽기 오류가 있으면 전체 가져오기를 중단하고 이전 자료를 유지합니다. 일부 파일을 조용히 생략하거나 잘라 넣지 않습니다.
- 이미지는 최대 50개, 장당 8MiB·합계 32MiB입니다. 확장자와 실제 파일 형식, 손상 여부를 검사하며 하나라도 실패하면 기존 자료를 유지합니다. 원시 이미지 목록에서 미리보기·경로·크기를 확인하고 필요 없는 이미지를 제외할 수 있습니다.
- **제작 시작**을 누르면 이미지를 한 장씩 연결한 글쓰기 모델에 전달합니다. 보이는 글자·도표·장면을 분석하고 Markdown 요약과 함께 목차·집필에 참고합니다. 이미지 분석은 장당 1회의 추가 요청이며 이미지 이해를 지원하는 글쓰기 모델이 필요합니다. 원본 데이터는 이미지 분석 요청에만 보내고 이후 집필에는 분석 내용과 출처 경로를 사용합니다.
- 분석 결과는 이미지마다 저장되므로 중단 후 완료한 이미지를 다시 요청하지 않고 이어갑니다. 제작 현황의 **집필 지시와 원시 소스 확인 → 분석 내용 확인**에서 요약·관찰·확인할 사항을 읽으세요. 흐린 글자나 그래프의 수치는 잘못 읽을 수 있으므로 출판 전에 원본과 대조하세요.
- 새 폴더나 여러 파일 선택은 현재 Markdown과 이미지 자료를 대체합니다. **MD·TXT 파일 하나 선택**과 Markdown 직접 수정은 이미지 자료를 유지합니다. 읽는 동안 중지할 수 있고, 직접 수정한 글은 이전 Markdown 파일 목록과의 연결을 해제합니다.
- 경로·파일 목록·원본 이미지·분석 기록은 제작 조건·JSON 백업·복원에 함께 보관됩니다. **원시 MD 받기**는 Markdown 합본만 내려받습니다. 이미지까지 보관하려면 JSON 백업을 사용하세요. 폴더 선택만으로 AI 요청을 보내지는 않습니다.
- 폴더는 선택한 시점의 파일을 읽습니다. 자동 동기화하지 않으므로 원본 파일이 바뀌면 다시 선택하세요. 폴더 선택을 지원하지 않는 브라우저에서는 필요한 MD·이미지 파일을 여러 개 직접 선택하거나 지원하는 브라우저를 사용하세요.

## Google 요청 오류 후 이어서 제작하기

제작이 멈추면 **제작 현황**에서 완료된 원고와 조건을 확인하세요. **API 설정 확인**은 같은 책의 연결 설정을 열고, 다시 연결하면 해당 책의 제작 현황으로 돌아옵니다. **이어서 제작**을 눌러야 다음 요청을 보냅니다. 이미 완료한 목차·집필 구간은 그대로 이어 사용합니다.

앱 업데이트 뒤에도 이전 오류 화면이 남아 있으면 작업을 백업하고 새로고침하세요. API 키는 탭 메모리에만 있어 다시 입력해야 합니다. Google HTTP 400은 확인 가능한 범위에서 키 만료·요청 형식·출력 한도·출력 구조·결제·지역 문제를 구분합니다. 원격 오류 본문이나 키는 화면과 백업에 포함하지 않습니다. 설정의 실제 생성 테스트는 별도 텍스트 요청 1회입니다.

## 내용에 맞는 표지와 내 배경

**디자인 → 내용에 맞는 AI 표지**를 누르면 현재 제목·부제·책 소개·독자·집필 지시와 본문의 주요 부분을 읽어 표지 콘셉트를 정한 뒤 그림을 생성합니다. 긴 책은 목차와 각 장의 앞·중간·끝을 고르게 발췌합니다. 선택 입력란에 원하는 장면·화풍·제외할 요소를 적을 수 있습니다. 자동 제작의 AI 표지도 같은 흐름을 사용합니다.

- 표지 한 장은 **텍스트 기획 1회 + 이미지 생성 1회**를 요청합니다. 별도 API 비용이 발생할 수 있으며, 취소하거나 실패하면 기존 표지는 유지합니다.
- 그림에는 글자를 넣지 않고 제목·부제·저자명을 앱에서 배치합니다. 생성된 표지의 내용 적합성과 시각적 품질은 출판 전에 확인하세요.
- **내 배경 이미지 → 배경 추가**에서 PNG/JPG/WebP 파일을 올립니다(8MiB 이하). AI/표지 이미지와 배경을 따로 보관하며 **사용할 표지 배경**에서 선택할 수 있습니다. 직접 올린 배경은 AI 입력으로 전송하지 않습니다.
- 가득 채우기/전체 보이기, 이미지 중심, 제목 위치, 글자 색상, 배경 보정 강도를 조절합니다. 이미지가 없으면 제목 위치만 설정할 수 있습니다. 미리보기는 입력에 맞춰 갱신됩니다.
- 수동 AI 표지 재생성은 새 표지를 보여 주되 기존 배경을 보존합니다. 자동 책 제작에서는 이미 선택한 사용자 배경을 유지합니다. **내 배경 삭제**는 표지 이미지를 남기며, **기본 표지로**는 두 이미지를 초기화합니다. 수정 이력에서 복원할 수 있습니다.
- 배경과 배치 설정은 JSON 백업·가져오기·자동 저장에 포함됩니다. 선택한 표지는 EPUB·HTML·인쇄용 PDF에 반영되고, 새 EPUB의 표지 썸네일에도 제목·부제·저자가 함께 들어갑니다. 글꼴과 리더 지원에 따라 표시 차이가 있을 수 있습니다.

## 작업 화면과 사용 안내

상단 **사용 안내(?)**에서 6단계 튜토리얼을 열 수 있습니다. 새 책 → 원고 → 윤문 → Google 연결 → 디자인 → 내보내기를 순서대로 살펴보거나 원하는 단계로 바로 이동하세요. 안내의 화면 열기 버튼은 해당 양식이나 편집 화면만 열며 원고를 바꾸거나 AI 생성을 시작하지 않습니다. 닫았다가 **안내 이어보기**로 돌아올 수 있습니다. 처음 보이는 시작 카드는 접을 수 있고, 안내는 언제든 다시 볼 수 있습니다.

- **빠른 실행:** 조건으로 책 만들기, 새 책, 원고 가져오기, 현재 책 백업을 작업 화면에서 바로 엽니다. AI 연결 상태도 표시합니다.
- **서재 검색:** 상단 돋보기 또는 `Ctrl / ⌘ + K`로 모든 책의 제목·장 제목·본문을 찾습니다. 위아래 방향키로 고르고 Enter로 해당 장을 엽니다.
- **쓰기 편의:** 이전·다음 장 이동, 작게/보통/크게 글자 조절, 집중 모드를 사용할 수 있습니다. 글자 크기는 편집 화면에만 적용되며 내보낸 책의 조판에는 영향을 주지 않습니다. 집중 모드는 Escape로 끝낼 수 있습니다.
- **키보드:** `Ctrl / ⌘ + S`는 현재 작업 저장, Escape는 열린 창 닫기입니다. 생성 중에는 작업 중지 버튼을 사용하세요. 한글 조합 중에는 탐색 단축키를 실행하지 않습니다.
- **화면 설정:** 안내 진행과 글자 크기는 원고와 별도의 기기 설정으로 저장합니다. 저장 공간을 사용할 수 없어도 안내와 글자 조절은 현재 탭에서 작동합니다. 집중 모드는 새로 열면 해제됩니다.

## 책처럼 읽는 프리뷰와 최종 파일

장별 **프리뷰**에서 Markdown 제목·강조·목록·표·도표를 렌더링합니다. **책 미리보기**는 표지·목차·본문을 페이지로 나누고 이전/다음 버튼, 방향키, 터치 넘김을 지원합니다. 넓은 화면은 펼친 책, 좁은 화면은 한 쪽씩 보여 주며, 기기의 동작 줄이기 설정을 따릅니다. 앱·독립 HTML·EPUB은 한국어 단어를 우선 유지하고, 긴 URL처럼 넘치는 문자열만 줄바꿈하도록 설정합니다. 실제 EPUB의 줄바꿈은 리더기와 사용자 글꼴 설정에도 영향을 받습니다.

**책 미리보기 → 에디터**에서 장을 선택해 제목·원고를 수정하고, 다시 **프리뷰**로 돌아가 배치를 확인할 수 있습니다. 메인 편집 화면과 책 미리보기 에디터 모두 이미지·앱 도표 복사/붙여넣기, 이미지 파일 넣기, HTML·스프레드시트 표의 Markdown 변환을 지원합니다. 이미지·도표 너비는 25~100%로 조절하며, 강조색과 선택 문장 강조도 적용할 수 있습니다.

저장된 기존 책에는 빠진 **시작말·맺음말**의 편집 가능한 초안을 추가하고, 적용 전 상태를 수정 이력에 보관합니다. 본문 장과 제작 진행 기록은 유지하며, 반복해서 열어도 앞뒤말을 중복 추가하지 않습니다. 정확히 **AI 생성 삽화**인 기본 캡션은 제거하고, 사용자가 쓴 다른 캡션과 대체 텍스트는 유지합니다. 시작말·맺음말 작성과 이 갱신에는 AI API 비용이 발생하지 않습니다. 자세한 사용법과 한도는 [책 미리보기·미디어 편집 안내](docs/BOOK-EDITOR-UPGRADE.md)를 참고하세요.

**HTML 내보내기**에도 같은 책 넘김 뷰어를 포함하므로 내려받은 단일 파일을 오프라인에서 열 수 있습니다. 인쇄용 출력은 정적 문서로 제공하며, EPUB의 페이지 전환은 사용하는 리더기가 결정합니다. PDF·EPUB에 웹 애니메이션이 그대로 적용되는 것은 아닙니다.

## 출판 준비 자동화와 경쟁 도구 비교

**출판·내보내기 → 출판 준비**에서 발행처·출판일·정가·ISBN·권리·AI 사용 내역을 입력합니다. 채널별 필수항목 대응표, 빈 장·이미지 참조·도표·ISBN 형식을 점검합니다. 저자는 교정·권리·기기 검수를 기록하며, 원고·표지·등록 자료·판권 정보가 바뀌면 재검토합니다.

- **판매용 JPG 표지 받기:** 제목·부제·저자·발행처와 현재 표지 디자인을 RGB JPEG로 합성하고 실제 픽셀·형식·용량을 검사합니다. KDP 권장1600×2560px을 지원하며, 국내·웹용 기본1600×2400px은 제출처 안내에 맞게 바꿀 수 있습니다. 국내 공통 의무 규격으로 제시하는 값은 아닙니다.
- **판본·유통·ISBN·납본 이력:** 판본, 개정 사항, 담당자, 진행 상태, 날짜, 증빙 링크를 입력하고 현재 내용의 검수 상태와 함께 기록합니다. 최근 100건을 보관합니다. 실제 외부 기관의 제출·승인·발급·납본 결과는 사용자가 확인합니다.
- **출판 준비 ZIP 만들기:** 판권을 추가한 EPUB, 책 넘김 HTML, 인쇄용 HTML, Markdown 원고·판권, 도서정보·점검표·경로별 대응표·판본 이력, 절차서, EPUBCheck 실행 도우미, Vivliostyle 설정을 묶습니다. 기본 14개 파일이며, 브라우저에서 생성한 JPG와 검사 보고서가 포함되면 16개입니다. 원래 작업 원고는 유지합니다.
- **EPUB 표준 검증:** 개발·배포에서는 고정된 EPUBCheck 5.4.0과 SHA-256 검증을 사용합니다. 대표 6개 EPUB 회귀 자료에서 오류 0·경고 0을 확인했습니다. 사용자가 이후 편집한 모든 책의 인증을 의미하지 않습니다. 각 책은 ZIP의 스크립트로 검사하고 실제 리더에서도 확인하세요.
- **선택형 전문 PDF 조판:** ZIP의 vivliostyle.config.json과 TYPESETTING.md는 Vivliostyle CLI 11.4.0으로 print.html을 A5 PDF로 조판하는 실행 설정입니다. Node.js 22.12.0 이상이 필요합니다. 앱의 PDF 버튼은 브라우저 인쇄를 사용하며, 전문 조판 PDF가 ZIP에 미리 생성되어 있지는 않습니다.

계정·계약·정산·ISBN·납본·판매 최종 신청은 해당 유통사에서 진행합니다. 국내 개인 저자는 제휴 유통 경로를 사용할 수 있고, KDP는 지원 언어의 실제 원고가 필요합니다. 구체적인 절차와 공식 출처는 [출판 실행 절차](docs/PUBLISHING-GUIDE.md)에 정리했습니다.

[calibre·Sigil·Pandoc·Vivliostyle 비교 보고서](docs/COMPETITIVE-ANALYSIS.md)는 우선순위별 구현 결과와 남은 격차를 구분합니다. EPUB 정밀 편집·광범위한 형식 변환·전문 조판·계정 기반 동시 협업은 계속 보완할 영역입니다.

## 출처 검토와 파일 협업

**윤문·교정 → 출처·검토 기록**에서 본문 문장과 등록 원문 발췌를 정확히 연결하고 원문 파일·행 위치를 확인합니다. 검토 의견을 남겨 해결 상태를 관리하고, 미해결 의견이나 변경된 출처가 없는 장에 검토 완료를 기록합니다. 본문·참고 자료가 바뀌면 완료 표시가 만료됩니다. 수치·인용 후보 표시는 확인을 돕는 규칙이며 사실을 자동 판정하지 않습니다.

**출판·내보내기 → 공유·검토 파일**에서 이름·역할·공유 범위를 확인하고 동의하면 전달용 파일을 받습니다. 원시 자료 추가 포함은 선택 사항입니다. 돌아온 파일은 공유 기준 판본·현재 작업·받은 작업을 비교하여 서로 다른 변경을 합칩니다. 같은 장에서도 기록된 기준과 문단 위치가 명확한 독립 수정은 병합 후보가 되며, 같은 문단·삽입/삭제·불명확한 충돌은 직접 선택합니다. 모든 충돌을 선택하고 적용에 동의해야 원고에 반영하며, 적용 전 상태는 수정 이력에 남깁니다.

파일을 직접 주고받는 방식으로 계정·서버 자동 동기화나 역할별 접근 제어는 제공하지 않습니다. 기본 공유 파일에도 원고·표지·본문 이미지·검토 의견·출처 발췌가 들어갑니다. API 키, 원본 DOCX/EPUB, 집필 실행 이력은 포함하지 않습니다. 자세한 흐름과 제한은 [출처 검토·협업 사용법](docs/COLLABORATION-REVIEW.md)을 참고하세요.

## 컴퓨터로 예제 만들기

상단 **컴퓨터로 예제 만들기**에서 실행 중인 프로그램을 조작하고 실습 화면을 원고에 반영합니다. 현재 연결 도우미는 **Windows 10/11, 같은 PC의 브라우저**를 지원합니다. 휴대폰에서 다른 PC로 연결하는 원격 서비스는 아닙니다.

1. 작업 화면의 **Windows 연결 도우미** ZIP을 내려받아 압축을 풉니다. Python 3.11 이상을 설치한 뒤 `start-windows.cmd`를 실행하세요. 처음에는 전용 가상 환경과 필요한 이미지·입력 라이브러리를 설치합니다.
2. 도우미 창에 표시된 연결 코드를 빌더에 입력합니다. 브라우저가 로컬 네트워크 접근을 묻는 경우 이 연결에 허용하세요. 도우미는 `127.0.0.1:8765`에서만 실행됩니다. 연결 코드와 Google/OpenAI API 키는 서로 다르며, 둘 다 책이나 백업에 저장하지 않습니다.
3. 메이플스토리 월드 에디터를 직접 실행하고 로그인한 다음 예제용 프로젝트를 엽니다. 빌더에서 해당 창을 선택하고 만들 예제·촬영할 장면·본문에 필요한 설명을 적습니다. 예: “이 연습용 프로젝트에서 발판 오브젝트를 하나 배치하고, 설정 화면과 실행 결과를 촬영해 초보자용 설명을 작성해 줘.”
4. **작업 시작** 후 선택한 창의 화면을 연결된 글쓰기 모델에 전달합니다. 모델은 화면을 보고 클릭·문자 입력·허용된 단축키·스크롤을 한 단계씩 요청하고, 의미 있는 지점에서 화면과 설명을 보관합니다. 단계마다 텍스트·이미지 이해 API 사용량이 발생합니다. 화면을 이해하는 모델이 필요하며, 연결 확인만으로 모든 모델의 조작 능력이 확인되지는 않습니다.
5. 중지 버튼 또는 도우미의 **F8** 긴급 중지를 사용하세요. 실행 중인 앱의 변경 사항은 그대로 남습니다. 한 번에 정한 단계 수까지만 작업하며, 로그인·결제·게시처럼 사용자 개입이 필요한 상황이나 처리할 수 없는 화면에서는 멈춥니다. 다시 시작할 때는 현재 화면에서 새 작업을 시작합니다.
6. 보관한 화면의 제목·캡션·추출한 설명을 편집하고 선택한 자료를 **본문에 반영**합니다. 현재 장 끝에 설명과 이미지 참조 줄을 추가하며 기존 원고를 유지합니다. 참조 줄을 다른 문단으로 옮겨 배치할 수 있습니다. 같은 캡처를 같은 장에 다시 넣으면 중복 추가하지 않습니다.

캡처 자료는 책당 20개·합계 32MiB, 장의 본문 이미지는 20개까지 보관합니다. 읽기 모드·책 미리보기·EPUB·HTML·인쇄용 PDF에 이미지를 포함합니다. JSON 백업에는 원본 캡처·작업 기록·본문 이미지가 들어갑니다. Markdown은 설명과 이미지 참조만 보관하므로 이미지까지 옮길 때는 JSON이나 EPUB을 사용하세요. 직접 올리는 스크린샷은 PNG를 지원합니다.

조작은 사용자가 선택한 창으로 제한하며, 임의 명령 실행이나 파일 탐색 API를 제공하지 않습니다. 창이 바뀌거나 연결·저장이 실패하면 작업을 중단합니다. 화면에 표시된 내용은 자료로 취급하고 별도의 사용자 지시를 우선합니다. 화면 인식과 생성 설명은 틀릴 수 있으므로 출판 전 원본과 대조하세요. 일부 하드웨어 가속 프로그램은 Windows 캡처에 빈 화면을 반환할 수 있습니다. 그 경우 직접 찍은 PNG를 올려 같은 원고 반영 흐름을 사용할 수 있습니다.

연결 도우미의 HTTP·조작 정책과 빌더의 작업 흐름은 모의 화면으로 검사했습니다. 이 개발 환경에서는 Windows 및 메이플스토리 월드 에디터를 직접 실행하지 못했습니다.

## 로컬 실행

Python 3가 설치된 폴더에서:

```sh
python -m http.server 4173 --directory dist
```

브라우저로 `http://localhost:4173`을 엽니다. 런타임 패키지 설치나 빌드 과정이 필요하지 않습니다. 모듈을 불러오기 위해 index.html을 파일로 직접 열지 말고 HTTP 서버로 실행하세요.

## 테스트

```sh
npm ci
npm test
node --max-old-space-size=512 --test --test-concurrency=1 ui-tests.mjs
python3 -m unittest discover -s companion -p 'test_*.py'
npm run validate:epub
```

`npm test`는 테스트 파일을 하나씩 실행하며 V8 old-space를 프로세스당 512MiB로 제한합니다. 전체 프로세스 RSS 상한을 뜻하지 않습니다. 중복 전체 실행, 큰 실패 출력, 종료되지 않은 DOM·타이머를 줄이는 방법과 이번 PC의 관측은 [메모리·테스트 운영 안내](docs/MEMORY-TESTING.md)에 정리했습니다.

EPUBCheck 검증 명령은 Java와 네트워크 접근이 필요하며 고정된 공식 배포본을 받아 체크섬을 검사합니다. 검증 결과는 CI 산출물로 보관합니다.

핵심 로직은 Node 기본 테스트 도구로 확인하며, UI 테스트에는 happy-dom, 저장 트랜잭션 테스트에는 fake-indexeddb를 사용합니다. 독립 레드팀 회귀 검증도 `npm test`에 포함됩니다. 실제 AI 호출·브라우저 인쇄·다운로드·EPUB 리더 렌더링은 실행 환경과 API 연결에 따라 별도 확인이 필요합니다.

연결 도우미 코드를 바꾸면 `python3 companion/package.py`로 다운로드 ZIP을 다시 만드세요. Python 검사는 가상 창과 Win32 API 스텁을 사용하며 실제 PC 입력을 발생시키지 않습니다.

## 구성

- `dist/app.js`: 편집 워크스페이스, 서재, 저장·이력, AI 제작 흐름
- `dist/production.js`: 원시 자료 보존, 분량 배정, 자료 분석·집필·보정, 중단 후 재개
- `dist/source-files.js`: 하위 폴더 Markdown·이미지 수집, 경로·용량·UTF-8 검사, 파일 목록 보존
- `dist/source-images.js`: 원시 이미지 형식·용량·경로 검사 및 저장 자료 검증
- `dist/registered-sources.js`: 새 책 원시 소스 등록·보존·검증
- `dist/document-import.js`: DOCX/EPUB 로컬 변환, 압축 안전 검사, 원본 문서 보존
- `dist/review-desk.js`, `dist/review-desk-ui.js`: 출처 위치·검토 의견·장별 완료 기록
- `dist/collaboration.js`: 동의 기반 공유 파일, 기준 판본 비교, 충돌 병합
- `dist/production-estimate.js`: 서적 분량 환산, 모델별 시간·비용 추정, 집필 승인 검증
- `dist/production-ui.js`, `dist/production.css`: 제작 조건·견적·승인·진행 화면
- `dist/storage.js`: 저장소 이전, 리비전 충돌 검사, 원본 보존과 복구
