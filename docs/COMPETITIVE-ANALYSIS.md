# Folio Studio와 전자책 제작 오픈소스 비교

갱신일: 2026-10-20. 비교 근거는 공식 저장소·매뉴얼과 현재 구현·검증 결과다. 사용자 수, 판매 전환율, 집필 생산성, 원고 품질을 비교 실험한 보고서는 아니다. 경쟁 도구의 확장 플러그인 전체에 대해 기능 부재를 단정하지 않는다.

Folio의 포지션은 **한국어 원시 자료에서 집필·검토·편집·출판 준비까지 연결하는 개인 저자용 작업실**이다. 이번 개선은 앞선 보고서의 P0/P1/P2 격차를 다뤘다. 기존 EPUB을 새 원고로 가져올 수 있게 되었으며, 정밀한 EPUB 내부 편집과 전문 조판은 성숙한 도구를 함께 사용하는 경로를 제공한다.

## 도구별 비교

| 비교 대상 | 공식적으로 확인한 강점 | Folio가 편리할 수 있는 작업 | 개선 후에도 남은 격차 |
|---|---|---|---|
| [calibre](https://github.com/kovidgoyal/calibre) | 다양한 형식 변환, 서지정보·서재 관리, 기기 전송, EPUB 편집, 뷰어·플러그인 | 브라우저에서 자료 등록→견적 승인→집필→출처 검토→출판 파일 준비를 연결 | EPUB 입력은 추가했지만 광범위한 변환·기기 전송·대형 서재 관리·원본 편집 수준의 EPUB 수정에는 미달 |
| [Sigil](https://github.com/Sigil-Ebook/Sigil) | EPUB2/3 편집, 목차·메타데이터, XHTML/CSS 점검·리포트, 플러그인, PageEdit 연계 | 내부 마크업을 몰라도 한국어 원고 편집·출처 의견·책 프리뷰·JPG 표지를 준비 | 가져온 EPUB을 편집용 원고로 변환하며 원본을 보관하지만, 내부 XHTML·OPF·CSS 직접 편집과 충실한 왕복 변환은 제공하지 않음 |
| [Pandoc](https://github.com/jgm/pandoc) | 다중 형식 입력·출력, 이미지·폰트·CSS 설정, 메타데이터·필터 자동화 | 명령행 없이 DOCX/EPUB을 불러오고 검토·승인·집필을 진행 | 입력 형식을 늘렸지만 복잡한 각주 링크·수학·문헌 인용·템플릿·Lua 필터·출력 형식 범위는 제한적 |
| [Vivliostyle CLI](https://github.com/vivliostyle/vivliostyle-cli) | HTML/CSS 조판, PDF·EPUB·Web Publication 출력, 미리보기·출판용 CSS 제어 | 자료와 내용 제작, 독립 HTML 책 넘김, 출판 절차·검수 기록 관리 | 고정 버전 실행 설정을 내보내는 연결 단계이며 앱 내부 전문 PDF 생성은 없음. 머리말·꼬리말·복잡한 페이지 규칙·인쇄 색상·출력 일관성 검증이 필요 |

경쟁 도구 기능 근거: [calibre 기능](https://calibre-ebook.com/about), [calibre 편집 매뉴얼](https://manual.calibre-ebook.com/edit.html), [Sigil README](https://github.com/Sigil-Ebook/Sigil#readme), [Pandoc EPUB](https://pandoc.org/epub.html), [Pandoc 매뉴얼](https://pandoc.org/MANUAL.html), [Vivliostyle CLI](https://docs.vivliostyle.org/en/cli/). 저장소 별 수를 기능 우위의 점수로 사용하지 않았다.

EPUBCheck는 생성기의 회귀 품질을 검증한다. CI에서 검사한 6개 자료가 통과했다고 사용자가 이후 편집한 모든 책을 인증된 것으로 표시하지 않는다. 앱은 각 책의 외부 검증을 계속 별도 단계로 안내한다. [EPUBCheck 공식 문서](https://www.w3.org/publishing/epubcheck/docs/cli/)

## 코드로 확인하는 강점

1. **자료를 보존하는 제작 흐름:** 원시 자료·가져온 원본 문서를 보관하고 별도 제작 책에서 집필한다. 단계별 저장·재개와 비용 승인으로 작업을 통제한다.
2. **검토할 근거를 보여 주는 편집:** 원문 발췌와 위치, 검토 의견과 해결 상태를 원고 옆에서 관리한다. 변경된 장을 이전 검토 완료 상태로 계속 취급하지 않는다.
3. **독자가 볼 형태의 확인:** 기본 Markdown 프리뷰, 책 넘김, 한국어 줄바꿈을 앱과 독립 HTML에서 제공한다. EPUB의 페이지 전환은 리더기 설정에 따른다.
4. **출판 준비물의 반복 생성:** 판권·메타데이터 대응표·별도 JPG·검수 보고서·판본 이력을 함께 묶는다. 국내 초보 저자가 준비 절차를 따라가기 쉬운 흐름을 제공한다.
5. **명시적인 파일 공유:** API 키나 원본 DOCX/EPUB 없이 필요한 원고·검토 파일을 전달한다. 원시 자료 추가 포함 여부를 선택하고 수신 변경은 비교·승인 후 반영한다.

이 강점은 기능과 작업 흐름에 대한 평가다. 경쟁 도구보다 더 정확한 원고를 만들거나 더 많은 판매를 낸다는 정량 근거는 아직 없다.

## 다음 개선의 순서

1. **실제 제출·읽기 검수 확대:** 국내 유통 경로와 지원 언어 KDP의 실제 제출 규격, EPUBCheck, 모바일 리더·화면낭독기 결과를 책별로 남긴다.
2. **입력 충실도 강화:** DOCX 다단계 번호·표, EPUB 주석 링크·SVG·수식·스타일의 손실을 문서 단위로 측정하고 낮춘다. 원본 보존은 유지한다.
3. **전문 조판 검증:** 제공한 Vivliostyle 설정을 실제 인쇄본에 적용하고 판형·페이지 규칙·긴 표·한글 출력의 검수 자료를 쌓는다.
4. **협업 정밀화:** 파일 교환의 동일 장 문장 병합을 개선한 후, 계정·권한·동기화 서비스를 별도 설계한다. 현재 파일 교환을 클라우드 동시 협업으로 설명하지 않는다.

동일한 원시 자료로 3만 자 한국어 실용서, 이미지 설명서, 표·도표 교육서를 준비해 작업 시간·변환 손실·EPUBCheck 결과·잘린 표/그림·출처 추적·저자의 사실 수정 건수를 기록하면 다음 우선순위를 객관화할 수 있다.
