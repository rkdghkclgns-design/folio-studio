# 도표와 상황 삽화의 기본 제작 방식

Folio Studio의 기본 시각 자료 제작 방식은 다음과 같습니다.

| 용도 | 제작 도구 | 결과 | 비용 경로 |
| --- | --- | --- | --- |
| 절차·관계·구조·비교 설명 | 실제 Claude | 자체 완결형 SVG | 로그인한 Claude의 포함 사용량 |
| 구체적인 상황·공간·캐릭터 예시 | ChatGPT·Codex 내장 이미지 생성 | PNG/JPEG/WebP | 해당 서비스의 포함 사용량 |

포함 사용량은 무제한이 아닙니다. 한도에 도달하면 완료한 자산을 보존하고 남은 작업을 기록합니다. 별도 API 키, 다른 유료 제공자, 추가 사용량 결제로 자동 전환하지 않습니다. API 연결을 사용하는 기존 기능은 별도 요금 방식임을 표시합니다.

## 실제 작업 순서

1. 책을 열고 **표지 & 삽화 → 도표·삽화 제작 및 가져오기**를 선택합니다.
2. **제작 요청서 받기**로 원문·장 ID·원문 확인값을 포함한 JSON을 저장합니다.
3. Codex에 이 요청서와 함께 기본 제작 방식으로 보강을 요청합니다. 장의 원문을 읽고 설명 도표와 상황 삽화를 배분합니다. 고정 비율을 모든 책에 강제하지 않습니다.
4. 실제 Claude 응답의 SVG와 내장 이미지 생성 결과를 보존합니다. 사용한 프롬프트, 제작 도구, 제작일, 대체 텍스트와 캡션을 기록합니다. Codex가 직접 작성한 SVG를 Claude 제작물로 표기하지 않습니다.
5. 아래 결과 형식의 JSON을 만들고 **도표·삽화 결과 가져오기**로 선택합니다. 원문 확인값은 요청서에서 그대로 가져옵니다.
6. 미리보기에서 각 장과 그림을 확인하고 **현재 책에 적용**합니다. 기존 책에 그림을 추가하며 책을 복제하지 않습니다. 적용 전 상태는 수정 이력으로 복원할 수 있습니다.
7. 책 미리보기와 EPUB·HTML을 확인하고 작업 백업을 저장합니다.

정적 웹사이트는 사용자의 Claude·ChatGPT 구독을 직접 호출하지 않습니다. 요청서 내보내기와 결과 가져오기는 이 경계를 명확하게 유지합니다. 새 책의 제작 폼은 이 방식을 기본으로 선택하며, 집필과 후속 그림 보강의 진행 상태를 구분합니다.

## 결과 파일 v1

```json
{
  "format": "folio-visual-assets",
  "version": 1,
  "book": {"title": "요청서의 책 제목", "author": "요청서의 저자"},
  "assets": [{
    "chapterId": "요청서의 장 ID",
    "chapterTitle": "요청서의 장 제목",
    "chapterHash": "요청서의 SHA-256",
    "kind": "diagram",
    "figure": {
      "id": "visual-chapter-01",
      "src": "data:image/svg+xml;base64,...",
      "alt": "그림 없이도 관계를 이해할 수 있는 설명",
      "caption": "본문에 맞는 예시 설명",
      "provenance": {
        "provider": "claude-svg",
        "createdAt": "2026-10-21T00:00:00.000Z",
        "prompt": "실제 제작 요청"
      }
    }
  }]
}
```

상황 삽화는 `kind: "illustration"`, `provider: "codex-imagegen"`과 PNG/JPEG/WebP 데이터 URI를 사용합니다. 한 결과 파일에는 장마다 한 그림을 넣습니다. 다음 보강은 새 ID와 최신 요청서로 진행합니다.

- 원문·표지·기존 그림은 유지하고, 장 끝에 `folio-asset` 참조와 새 그림을 추가합니다. 편집기에서 위치·크기·강조색을 조정할 수 있습니다.
- 같은 결과의 재적용은 중복을 만들지 않습니다. 같은 ID의 다른 그림, 제작 후 수정된 원문, 다른 책, 중복된 장은 적용 전에 거부합니다.
- 백업을 가져와 ID가 바뀐 책은 책 제목·저자와 유일한 장 제목·원문 확인값으로 연결합니다. 애매한 장은 자동 선택하지 않습니다.
- SVG는 기존의 엄격한 허용 목록 검사를 통과해야 합니다. 외부 리소스·스크립트·이벤트·foreignObject 등은 사용할 수 없습니다.
- 그림마다 최대 12MB, 장마다 최대 20개, 결과 JSON 최대 128MB입니다. 원본 이미지와 적절히 압축한 배포용 이미지를 함께 보관하는 것을 권장합니다.
- 제작 기록은 검토·백업용입니다. 책에 일괄적인 ‘AI 생성 삽화’ 캡션을 붙이지 않습니다. 내용에 맞는 설명과 접근성 대체 텍스트를 사용합니다.
- 개인 원고·제작 결과·프롬프트는 공개 사이트 소스 저장소에 커밋하지 않습니다. 사이트 배포와 개인 책의 공개 출판은 별개입니다.

## 구현 위치

`dist/visual-workflow.js`는 기본 경로, 제작 요청서, 결과 검증, 중복 방지, 변경 충돌 확인을 담당합니다. `dist/export.js`는 SVG와 제작 기록의 검증 및 EPUB 자산 처리를 담당합니다. 이 흐름은 외부 API 요청을 수행하지 않습니다.
